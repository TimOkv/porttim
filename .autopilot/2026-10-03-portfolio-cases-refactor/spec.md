# Спецификация: портфолио PortTim — стек, опыт EasyCode и 9 кейсов

## Задача

У меня есть сайт-портфолио, но он рассказывает не про меня: девять кейсов в нём условные, с
художественными заголовками и выдуманными брендами на картинках, стек показан пятью парными
кнопками, а про мою работу в EasyCode нет ни слова. Человек, который откроет сайт перед разговором
со мной, не увидит ни моих реальных проектов, ни того, что каждый из них дал бизнесу. При этом два
кейса сделаны на чужой платформе EasyLab — и сайт не должен создавать впечатление, будто движок
написал я.

## Решение

Сайт остаётся тем же по виду и устройству, но наполняется настоящим содержанием:

- полоса из четырёх цифр под первым экраном, каждая из которых подтверждается кейсом ниже;
- ровная сетка из девяти текстовых карточек кейсов с тремя фильтрами; в карточке — формат,
  название, выделенный результат, суть работы и теги;
- окно кейса с ценностью для бизнеса и кнопкой, которая открывает личный чат в Telegram с
  черновиком, где уже названо, какой кейс заинтересовал;
- новая секция «Обо мне» после кейсов: абзац про EasyCode, честная подача молодого специалиста и
  ряд коротких фактов;
- секция стека из трёх карточек-групп, где все 14 технологий видны сразу;
- все кнопки связи ведут прямо в личный диалог `@opskeeper`.

Первый экран (заголовок, подпись под именем, портрет) не меняется. Сайт никуда не публикуется.

## Что показал осмотр кода (R26)

- Всё содержание лежит в одном модуле данных; компоненты берут тексты оттуда. Это сохраняется.
- Секции страницы: шапка → герой → цифры → кейсы → стек → контакты. Блока «о себе» нет.
- Карточка кейса сейчас состоит из нарисованного кодом превью (шесть видов схем) и текста; три
  карточки из девяти крупнее остальных.
- Ссылка в Telegram строится в двух местах независимо: в модуле данных (её и использует страница)
  и в отдельном модуле ссылок, которым пользуется только короткий адрес `/tg`. Имя аккаунта
  продублировано в обоих.
- Автотесты привязаны к старым заголовкам, старым цифрам полосы и к кнопке стека «Python & API».
- Тесты запускаются против сервера на порту 3100; сейчас там работает сервер со старой сборкой, и
  конфигурация тестов переиспользует его, если он жив.
- В проекте есть набор заготовок интерфейса (`ui/`), которыми страница не пользуется.

## Решения по реализации

1. **Содержание остаётся в одном модуле данных, схема расширяется.** Почему: владелец выбрал
   структуру Codex базой; компоненты уже читают тексты оттуда. Экспорты `profile`, `copy`, `metrics`,
   `categories`, `projects`, `stack` сохраняют имена. Добавляется `about`.
   Что значит «база сохраняется»: тот же файл на том же месте, те же имена экспортов, у кейса
   остаются поля `id`, `number`, `category`, `title`, `description`, `tags`; `profile`, `copy` и
   форма записи `metrics` не меняют устройства. Уходит только то, что отменил сам владелец:
   `visual` и `preview` — «Без картинок»; `featured` — «Все карточки одинаковые»; `subtitle` и
   `stats` заменены полями `format`, `label` и `result`, потому что формат и метрика теперь
   заданы у каждого кейса явно; пять пар в `stack` — «Три карточки-группы».
2. **Форма кейса.** Поля `subtitle`, `stats`, `visual`, `featured`, `preview` уходят вместе с
   превью; добавляются подкатегория, формат, выделенный результат, ценность и необязательная ссылка:

   ```ts
   export type Category = "Web" | "AI & Bots" | "Automation";
   export type Project = {
     id: string;
     number: string;
     category: Category;          // фильтр
     label: string;               // подкатегория из задачи: "Web / EdTech"
     format: string;
     title: string;
     result: { value?: string; text: string };  // value — только цифра из задачи
     description: string;
     value: string;               // ценность для бизнеса
     tags: string[];
     url?: string;                // публичная ссылка; пока не задана ни у одного
   };
   export type StackGroup = {
     icon: "layers" | "workflow" | "sparkles";
     name: string;
     detail: string;
     items: string[];
   };
   ```
3. **Стек — три группы вместо пяти пар.** `stack` становится массивом `StackGroup`. Секция перестаёт
   быть интерактивной: состояние «выбранного чипа» и строка-пояснение удаляются. Почему: владелец
   выбрал вариант, где все 14 технологий видны без кликов.
4. **Цифры, зависящие от числа кейсов, считаются из данных.** Первая цифра полосы, счётчик фильтра
   «Все», факты «число кейсов» и «число направлений». Почему: иначе десятый кейс рассинхронизирует
   четыре места.
5. **Кнопки фильтров строятся по категориям, у которых есть кейсы.** Почему: пустая кнопка — тупик.
6. **Ссылки в Telegram строит один модуль ссылок.** Он — единственное место с именем аккаунта и
   правилом проверки. Модуль данных берёт ссылку из него и больше не содержит своей копии правила;
   компонент кнопки связи принимает точку входа или кейс и получает ссылку оттуда же. Почему: сейчас
   имя аккаунта продублировано в двух файлах, и комментарий в коде просит держать их в согласии
   вручную.
7. **Новая секция — отдельный компонент** в том же плоском каталоге компонентов и в том же стиле
   (класс-ориентированные стили в общем файле стилей, стеклянные панели, надзаголовок + заголовок с
   акцентом). Почему: так устроены все соседние секции.
8. **Карточка без превью, сетка без выделенных.** Компонент превью и его стили удаляются;
   модификатор «крупной» карточки и связанные с ним правила сетки удаляются. Выделенный результат в
   карточке — крупная цифра (если есть) и строка текста под названием.
9. **Короткие адреса `/tg` сохраняются** и работают с новыми идентификаторами кейсов.
10. **Заготовки интерфейса в `ui/` не трогаются.** Они не используются страницей и не входят в
    задачу; удалять их никто не просил.
11. **Тесты переписываются под новое содержимое** и берут ожидаемые количества из модуля данных.
    Перед прогоном старый сервер на порту 3100 останавливается, проект пересобирается.
12. **Версия Next.js в проекте новее привычной** — по правилу из памяти проекта перед правкой кода
    читается соответствующий раздел документации из установленного пакета.
13. **Новых зависимостей нет.**
